## 21. المعمارية المنفَّذة: Worker واحد على Cloudflare

هذا الفصل يصف ما هو **قائمٌ فعلاً**، ويُقرأ قبل الفصلين 2 و11 المكتوبين على
مكدس سابق. القواعد والمجال في بقية الفصول لم تتغيّر؛ ما تغيّر هو أين تعمل.

### 21.1 لماذا Worker واحد

كانت أربعة تطبيقات في أربعة أماكن: موقعٌ ساكن على Worker، وتطبيقان على
Workers بلا مسار على النطاق، وواجهة برمجية بلا استضافة أصلاً. والنتيجة
المقاسة على النطاق الحيّ: `/app/cart` و`/search` ترجعان **404**،
و`api.talisham.com` لا خادم خلفه.

| المسار | ما يُخدَم | المصدر |
| --- | --- | --- |
| `/api/v1/*` | الواجهة البرمجية (Hono) | `apps/api/src/worker.ts` |
| `/app/*` | تطبيق السلة والحساب | `apps/app` |
| `/admin/*` | لوحة التحكم وواجهة المندوب | `apps/admin` |
| `/media/*` | صور المنتجات من R2 | `apps/api/src/modules/storage.ts` |
| ما عداه | الموقع الساكن (62 صفحة) | `apps/site` |

وأصلٌ واحد يعني: بلا CORS، وبلا نطاق ثانٍ للواجهة، وبلا رمز دخول يعبر
أصلين — وهي ثلاثة مصادر أعطال حُذفت لا حُلّت.

### 21.2 الموارد

| المورد | الربط | ما يحمله |
| --- | --- | --- |
| D1 | `DB` | كل الجداول (51 جدولاً) |
| KV | `KV` | رموز الدخول، مفاتيح التفرّد، عدّادات حدّ المعدل |
| R2 | `MEDIA` | صور المنتجات |
| Assets | `ASSETS` | الموقع الساكن وحزمتا التطبيقين |
| Cron | — | كل دقيقة: الكنس · كل خمس: التنبيهات · يومياً: الحذف المستحق |

القاعدة **ربطٌ لا رابط اتصال**: لا منفذ مفتوح على الإنترنت، ولا جدار ناري
يُضبط، ولا كلمة سرّ تُدوَّر، ولا اتصال يُعدّ أو يُجمَّع.

### 21.3 ثمن D1 وكيف دُفع

SQLite ليست PostgreSQL، وثلاثة فروق كان لا بدّ من دفع ثمنها صراحةً:

**١) لا معاملات تفاعلية.** لا يمكن على D1 أن تقرأ داخل معاملة ثم تقرّر ثم
تكتب. وكانت خمس عشرة معاملة كذلك، أخطرها خصم المخزون.

الحلّ لم يكن إضعاف الضمانة بل نقل مكانها: القراءة تبقى قبل الكتابة لتعطي
رسالةً مفهومة، والكتابات كلها تُرسَل **دفعةً ذرّية** ترتدّ كاملةً إن رُفض
أيّ سطر منها. والحَكَم صار القاعدة نفسها: قيد `reserved <= on_hand` ومحفِّز
تطابق الوحدات. فما يصل الرفّ لا يُباع مرتين ولو تسابق عليه اثنان — وهو
الثابت نفسه الذي كشف أربعة عيوب في الفحص السابق. التنفيذ في
`apps/api/src/common/batch.ts`.

**٢) لا محفِّزات مؤجَّلة.** في PostgreSQL كان محفِّز التطابق يُؤجَّل إلى نهاية
المعاملة، فلا تُزعجه الحالات الوسطى: تُختم عشر وحدات SOLD واحدةً واحدةً ثم
يُنقص العدّاد. وSQLite لا يعرف التأجيل.

فنُقل الفحص إلى حيث تنتهي كل عملية مخزون فعلاً: تحديث `version` في
`inventory_levels`. وصار ترتيب الكتابة جزءاً من العقد لا تفصيل أسلوب:
تُختم الوحدات أولاً، ثم يُضبط العدّاد أخيراً. والمعنى محفوظ: الانحراف
يُرفض، وقد أُثبت ذلك بمحاولة كسرٍ مباشرة على القاعدة.

**٣) لا أنواع معدودة.** خمسة وثلاثون `ENUM` صارت نصوصاً محروسة بـ 62 قيد
`CHECK` مولَّدة آلياً من `prisma/enums.json` — فالقيمة التي كانت القاعدة
ترفضها ترفضها اليوم. والقيود تُحقن في الترحيل بخطوة صريحة
(`prisma/apply-constraints.mjs`) لأن SQLite لا يقبل إضافة قيد إلى جدول قائم.

وفرقٌ رابع صغير: النمط `GLOB` الطويل بأصنافه العشرة يرفضه D1 نفسه بـ«LIKE
or GLOB pattern too complex»، فصارت فحوص الصيغة بنيويةً بـ`substr` وصنفٍ
منفيّ واحد — والنتيجة واحدة.

### 21.4 ما حُذف لأنه مات

| المحذوف | لماذا |
| --- | --- |
| NestJS | إطارٌ كامل لأجل توجيه؛ الخدمات نفسها بقيت بلا تغيير وحلّ Hono محلّ الغلاف |
| Redis | لا Redis داخل Worker — وKV يؤدّي ما كان يؤدّيه |
| Meilisearch | لا خادم بحث داخل Cloudflare، والمسار الذي كان «احتياطاً» أُثبت في الفحص أنه يعطي النتائج نفسها في كل استعلام |
| قرص الصور المحلي وS3 | لا قرص في Worker، وربط R2 لا يحتاج مفاتيح تُدار |
| Docker Compose (تطوير وإنتاج) | لا حاويات في مسار النشر |
| خادم Node وملفّ إقلاعه | منفَّذ واحد يكفي، ومنفَّذان يعنيان اختلافاً صامتاً بين ما يُختبَر وما يُنشَر |
| ثلاثة ملفات `wrangler.jsonc` | إعدادٌ واحد لـWorker واحد |

القاعدة التي حكمت الحذف: شيفرةٌ لا تعمل في الإنتاج تُوهم بخيارٍ غير موجود،
وتُصان بلا فائدة، وتُقرأ فتُضلّل.

| دور غير معروف | `CHECK constraint failed` |
| ترحيل من الصفر | يمرّ: 51 جدولاً · 138 فهرساً · محفِّزان |

### 21.6 التشغيل

```bash
pnpm run build:worker          # الموقع + التطبيقان + نص الـWorker
pnpm run db:migrate:local      # ترحيل القاعدة المحلية
pnpm run db:seed               # بذرة الكتالوج محلياً
pnpm run worker:dev            # كل شيء على http://localhost:8787

API_BASE=http://127.0.0.1:8787/api/v1 pnpm run test:e2e
```

والنشر بدفعةٍ إلى `main`: الترحيل أولاً ثم النشر، بهذا الترتيب — نصٌّ جديد
يقرأ عموداً لم يُنشأ بعدُ يفشل عند أول طلب.
