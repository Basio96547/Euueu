# تالي شام — متجر إلكتروني سوري متخصص في الهواتف الجوالة

> متجر إلكتروني عربي (RTL) متخصص في بيع الهواتف الجوالة وملحقاتها داخل سوريا، مبني بمنهج **الجوال أولاً (Mobile-First)** على شبكات بطيئة وأجهزة متواضعة، بواجهة **Astro** لصفحات البحث وتطبيق تفاعلي للسلة والحساب، ونظام تصميم **Liquid Glass**، و**الدفع عند الاستلام** طريقةً وحيدة.

**حالة المشروع:** مرحلة التخطيط. هذا المستودع يحتوي الخطة المرجعية الكاملة للتنفيذ (Blueprint) موزّعة على تسعة عشر فصلاً في مجلد [`docs/`](docs/). لم تبدأ كتابة الكود بعد.

| البند | القيمة |
| --- | --- |
| الاسم والنطاق | تالي شام · `talisham.com` · `api.talisham.com` · `admin.talisham.com` |
| السوق | سوريا — دمشق وريفها، حلب، حمص، حماة، اللاذقية، طرطوس أولاً، ثم بقية المحافظات |
| التخصص | الهواتف الجوالة والملحقات (جديد، مفتوح العلبة، مجدد، مستعمل بإفصاح) |
| منهج التصميم | الجوال أولاً + PWA + RTL + نظام Liquid Glass |
| الواجهة | Astro 5 لصفحات الـSEO (صفر JavaScript + جزر React) · React SPA للتطبيق ولوحة الإدارة |
| الخلفية | NestJS · PostgreSQL · Prisma · Redis · Meilisearch · تخزين متوافق مع S3 |
| النشر | Cloudflare (Pages/Workers) مع خطة بديلة موثّقة وقابلية نقل كاملة بـ Docker |
| الدفع | **الدفع عند الاستلام فقط** (نقداً بالليرة السورية) |
| المستودع والحزم | `talisham` · `@talisham/*` |

## نموذج الدفع: عند الاستلام فقط

لا توجد بوابة دفع إلكتروني في هذا المشروع، ولا خطوة دفع في مسار إتمام الطلب. العميل يطلب، ويتلقى **تأكيداً** (زر عبر واتساب، وتُصعَّد إلى مكالمة عند عدم الرد)، ثم يستلم جهازه ويدفع نقداً للمندوب أو في مكتب النقل.

```ts
// packages/types/src/order.ts
export type PaymentMethod = 'COD'                     // القيمة الوحيدة اليوم
export type PaymentStatus = 'PENDING' | 'COLLECTED' | 'PARTIAL' | 'REFUNDED'
```

- إضافة طريقة دفع مستقبلاً = قيمة جديدة في `payment_method` وخطوة إضافية في التدفق، دون إعادة هيكلة.
- حالة الطلب (تنفيذ) منفصلة عن حالة التحصيل (مال)، فلا يختلط تتبّع الشحنة بتتبّع النقد.
- التحصيل النقدي يُطابَق يومياً مع المندوبين ومكاتب النقل في `cash_settlements`، والفروقات تُرصد آلياً.

## القرارات المرجعية الموحّدة

هذه القرارات مُلزِمة لكل الفصول، وأي تعارض يُحسم لصالح ما هنا:

| الموضوع | القرار | المرجع |
| --- | --- | --- |
| التسعير | مرجع بالدولار `price_usd_cents` (`BIGINT`)، والعرض بالليرة السورية عبر `fx_rates` بسعر يحدّثه المدير | [الفصل 7](docs/07-catalog.md) |
| صلاحية سعر الصرف | لكل سعر `valid_until`؛ وعند تقادمه يتوقف استقبال الطلبات تلقائياً أو يُطبَّق هامش أمان — لا بيع بسعر ميت | [الفصل 7](docs/07-catalog.md) |
| تثبيت السعر | `orders.fx_rate` و`orders.total_syp` يُثبَّتان عند التأكيد وصلاحيتهما 48 ساعة ثم يُعاد التسعير | [الفصل 8](docs/08-orders.md) |
| الضريبة | لا ضريبة قيمة مضافة؛ `tax_rate_bp` قابل للتهيئة وقيمته الافتراضية صفر | [الفصل 7](docs/07-catalog.md) |
| المعرّفات | `UUIDv7` داخلي، ومعرّف عام منفصل غير زمني لكل مورد يظهر في رابط عام | [الفصل 3](docs/03-data-model.md) |
| كمية المخزون | `inventory_levels(on_hand, reserved, …)`، والمتاح = `on_hand − reserved`، والتطابق مع وحدات الأجهزة مفروض داخل المعاملة | [الفصل 3](docs/03-data-model.md) |
| وحدات الأجهزة | `device_units` يحمل IMEI والحالة والكفالة ورابط بند الطلب | [الفصل 3](docs/03-data-model.md) |
| مواصفات السوق | `device_origin` و`part_code` و`dual_sim` و`warranty_type` و`warranty_months` و`condition` إلزامية على مستوى المتغيّر | [الفصل 3](docs/03-data-model.md) |
| حالات الطلب | `PENDING_CONFIRMATION → PROCESSING → SHIPPED → OUT_FOR_DELIVERY → DELIVERED` وما يتفرع عنها | [الفصل 8](docs/08-orders.md) |
| رقم الطلب | `TS-YYMM-NNNNNN` مع قيد تحقق في قاعدة البيانات | [الفصل 8](docs/08-orders.md) |
| مُهَل الحجز | حجز أوّلي قصير عند إنشاء الطلب، يُمدَّد بعد التأكيد؛ ونافذة التأكيد 48 ساعة | [الفصل 7](docs/07-catalog.md) |
| العنوان | محافظة + مدينة + حي + شارع + **معلم قريب إلزامي** + رقمان للتواصل | [الفصل 3](docs/03-data-model.md) |
| الشحن | مندوبو المتجر داخل المدن، ومكاتب النقل بين المحافظات، والبريد — بتتبّع يدوي لا webhooks | [الفصل 8](docs/08-orders.md) · [17](docs/17-delivery-ops.md) |
| OTP والإشعارات | واتساب قناة أساسية، وSMS احتياطي يُختبر أسبوعياً، وأرقام `+963` | [الفصل 9](docs/09-security.md) |
| حدود المعدل | جدول الفصل 9 هو المصدر الوحيد، ولا تُكرَّر القيم في أي فصل آخر | [الفصل 9](docs/09-security.md) |
| ميزانيات الأداء | جدول الفصل 5 هو المصدر الوحيد، والقياس المرجعي على 3G بطيء لا على 4G | [الفصل 5](docs/05-mobile-ux.md) |
| نظام التصميم | التصميم الصلب هو الأساس، وLiquid Glass تحسين تدريجي يُفعَّل عند توفر القدرة | [الفصل 5](docs/05-mobile-ux.md) |
| الصيانة | إصلاح تلقائي أسبوعي، وترقية مكتبات كل شهرين عبر Renovate ببوابات قبول | [الفصل 11](docs/11-devops.md) |

## تشغيل المشروع

المتطلبات: Node 22، pnpm 10، Docker (اختياري — الموقع يعمل بدونه).

```bash
pnpm install

# الواجهة وحدها: تعمل من بذرة الكتالوج مباشرة، بلا قاعدة بيانات
pnpm --filter @talisham/site dev        # http://localhost:4321

# المكدس الكامل
cp .env.example .env
pnpm dev:up                              # postgres · redis · meilisearch · minio · mailpit
pnpm db:migrate && pnpm db:seed
psql "$DATABASE_URL" -f apps/api/prisma/sql/constraints.sql   # القيود والمحفِّزات
```

### ما جرى التحقق منه فعلياً

شُغّل النظام كاملاً على PostgreSQL 16 حقيقي وأُثبتت الرحلة من طرف إلى طرف:

| الفحص | النتيجة |
| --- | --- |
| بذر الكتالوج | 22 منتجاً · 24 متغيّراً · 7 تعريفات شحن |
| حساب المستحق النقدي | 16,600 سنتاً × 12,850 = 2,133,100 ← **2,133,000 ل.س** وفرق تقريب −100 مخزَّن |
| رفض الطلب على منتج تجريبي | `409 DEMO_PRODUCT_NOT_ORDERABLE` |
| مفتاح التفرّد على إنشاء الطلب | إعادة الإرسال أعادت `TS-2607-000001` نفسه ولم تنشئ طلباً ثانياً |
| انتقال حالة غير مسموح | `409 INVALID_TRANSITION` عند محاولة التسليم قبل الشحن |
| دورة الحالات الكاملة | تأكيد ← تجهيز ← شحن ← خروج للتوصيل ← تسليم وتحصيل |
| مفتاح التفرّد على التحصيل | إعادة الإرسال لم تحصّل مرتين |
| **محفِّز تطابق المخزون** | رفض الإيداع: «انحراف مخزون: 1 وحدة بحالة IN_STOCK مقابل on_hand = 8» |
| **توقّف البيع عند تقادم سعر الصرف** | `503 FX_STALE_HALT` بعد 13 ساعة من انتهاء الصلاحية |
| **هامش الأمان في فترة السماح** | 12,850 ← 13,236 تلقائياً (‏3%) |
| بناء الموقع | صفر ملفات JavaScript · 25 كيلوبايت لأول زيارة |
| بناء التطبيقين | 65 كيلوبايت مضغوطاً لكل منهما (الميزانية 170) |
